# Pragmatics

Status: INTRINSIC SYSTEM / DESIGN

## Purpose

`pragmatics/` models what signals are doing in context: requesting, refusing, promising, joking, teasing, warning, negotiating, roleplaying, quoting, correcting, implying, coordinating, or otherwise acting socially beyond literal proposition content.

Pragmatics is related to semantics and social cognition but remains distinct from both.

## Core separation

```text
LITERAL_CONTENT
!= PRAGMATIC_FORCE
!= SOCIAL_EFFECT
!= AUTHORITY
```

A sentence can have stable literal content while its force changes with speaker, relationship, timing, role, shared convention, or present uptake.

## Pragmatic object

May carry:

- utterance/action ref;
- candidate speech/social act;
- speaker/addressee;
- context;
- relationship/local-convention refs;
- literal semantic refs;
- inferred intent;
- confidence/alternatives;
- current uptake;
- correction/withdrawal state;
- authority/consent relevance without silently supplying either.

## Local conventions

Shared interaction history may create local conventions, callbacks, code words, ritualized forms, humor, or roleplay grammar.

These are scoped and currentness-sensitive.

```text
PAST_SHARED_FRAME != PERMANENT_CURRENT_FRAME
```

## Uptake

Pragmatic meaning depends partly on how participants are actually coordinating now. Fresh rejection, clarification, confusion, or withdrawal changes the live model.

## Permission boundary

Recognizing an imperative/request/consent-relevant utterance does not itself authorize an effect. Pragmatics identifies candidate force; authority/consent systems adjudicate eligibility.

## Failure modes

- literal sentence meaning substituted for pragmatic force;
- old joke/roleplay frame treated as permanent;
- inferred intent defended after direct correction;
- local convention generalized globally;
- command classification treated as legitimate authority;
- social pressure misread as freely authored commitment.
